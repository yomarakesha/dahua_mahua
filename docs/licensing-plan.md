# План лицензирования (офлайн, без сервера)

_Черновик. Составлен 2026-07-07. Язык: русский (тех. термины — на английском).
Приложение работает on-prem/офлайн у клиента; лицензия проверяется локально, без интернета._

## Базовый механизм: подписанный лицензионный файл (Ed25519)

1. Один раз генерируем пару ключей. **Приватный** — у нас (офлайн, в сейфе/секрет-менеджере). **Публичный** — вшит/скомпилирован в backend.
2. Лицензия = маленький JSON + подпись:
```json
{
  "customer": "ООО Ромашка",
  "site_id": "romashka-01",
  "issued": "2026-07-07",
  "expires": "2027-07-07",          // null = бессрочно
  "features": ["playback","hikvision"],
  "max_cameras": 64,
  "max_nvrs": 8,
  "hardware_id": "a1b2c3...",       // привязка к машине
  "sig": "<Ed25519 подпись всего выше>"
}
```
3. Backend при старте: проверяет подпись публичным ключом, сверяет `expires` и `hardware_id`. Невалидно/просрочено/чужая машина → не стартует (или read-only/демо).

Библиотека: Python `cryptography` (Ed25519). Свою крипту не пишем.

## Привязка к железу (node-lock)

`hardware_id` = хеш стабильных ID машины: Windows `MachineGuid`/UUID материнки/серийник диска; Linux/Docker `/etc/machine-id`, DMI.
**Docker-нюанс:** пробросить в контейнер идентификатор ХОСТА (смонтировать `/etc/machine-id` или передать через env) — иначе fingerprint эфемерный. Брать 1–2 стабильных фактора (баланс защита ↔ поддержка при апгрейде железа).

## Процесс выдачи (полностью офлайн)

1. Клиент ставит → экран лицензии показывает **«Отпечаток машины»** (код).
2. Клиент присылает код + оплата.
3. Мы CLI-утилитой (с приватным ключом) генерим `license.lic` под этот отпечаток + срок + лимиты.
4. Отправляем `.lic`; клиент кладёт в папку / вставляет в UI → активация. Дальше офлайн навсегда (до `expires`).
5. Продление = новый `.lic` (отпечаток тот же).

## Честно про угрозы

Офлайн-защиту можно взломать патчем самой проверки (не подделкой — подделать без ключа нельзя, но вырезать `if` можно). Реальная защита:
- **Компиляция backend** (Nuitka/Cython).
- Несколько избыточных, размазанных, обфусцированных проверок.
- **Крипто-привязка функциональности**: из лицензии выводим ключ, которым расшифровывается что-то нужное для работы → «вырезать проверку» = сломать приложение.
- + Юридический договор. Рынок — локальные фирмы, не реверсеры → практический барьер достаточен.

## Что кодирует лицензия (энтайтлменты)

Срок; тип (trial/perpetual); `max_cameras`/`max_nvrs` (не даст добавить сверх); список модулей; имя клиента (видно в UI → деанонимизирует пиратку).

## Варианты (по силе/усилиям)

| Вариант | Защита | Усилия | Кому |
|---|---|---|---|
| **1. Свой `.lic` Ed25519 + hardware-id** | Средняя | Низкие | **Старт (MVP)** |
| **2. + Nuitka-компиляция + крипто-привязка функций** | Хорошая | Средние | Когда пойдут продажи |
| **3. Готовый offline-SDK (Keygen / Cryptolens / LicenseSpring)** | Хорошая | Небольшая подписка | Не хотим свою крипту |
| **4. USB-донгл (Wibu CodeMeter / Thales Sentinel)** | Максимальная офлайн | Дорого + логистика | Крупные/критичные |

## Рекомендация

- **MVP:** Вариант 1 (свой `.lic` + hardware-id, проверка в backend, CLI-генератор у нас). Ноль инфраструктуры, полностью офлайн.
- **Потом:** Вариант 2 (компиляция + крипто-привязка).
- **Донгл** — в запас для крупных клиентов.
- Цель: не «невзламываемо» (невозможно), а «барьер дороже честной покупки» + договор.

## Реализация в нашем стеке (модуль, отдельно)

- `backend/app/licensing.py`: загрузка/проверка `.lic`, hardware-id, enforcement на старте + периодически; отдаёт статус в API.
- Экран в UI: «Отпечаток машины» + поле/загрузка `.lic` + статус лицензии (срок, лимиты, клиент).
- CLI `tools/issue_license.py` (у нас): вход — отпечаток + параметры, выход — подписанный `.lic`.
- Хорошо стыкуется с будущей контейнеризацией (Docker) и планом деплоя ([[deployment-and-scaling-plan]]).
